# vLLM patches for the Qwen3.8-27B deployment

**These patches are now commits on this branch.** `qwen3.8-27B` is upstream
`acb0f1dcd` (`vllm 0.27.2rc1.dev110+gacb0f1dcd`) with the twelve changes below
applied in order, so the deployment installs directly:

```bash
VLLM_USE_PRECOMPILED=1 uv pip install git+https://github.com/gabewillen/vllm@qwen3.8-27B
```

No venv-local patching and no lane branches are needed. The patch files and
`apply-to-venv.sh` are kept for reference and for porting onto a different
upstream base.

---


None of these eleven changes is in any vLLM release. Installing this branch
carries all of them. If you instead run a stock wheel in a venv, apply them
with `apply-to-venv.sh` after every venv rebuild, which silently drops them.

(a) **Two-phase prefill.** The frontend renders one prompt per level and ships their longest common token prefix minus one as the body plus one tail per level; the scheduler caps the first chunk at the body so it is a non-final prefill chunk - no token sampled, no draft proposed - and asks the worker for the body's last row. The boundary is quantised to a KV block (1648 tokens on this hybrid profile); cached blocks past the body are never adopted, so a fully prefix-cached prompt still produces a row. (b) **Online memory** (`vllm/v1/core/sched/effort_memory.py`): a FIFO ring (per-session cap `memory_size/64`) of L2-normalised pooled states inserted at request finish, valued by the reasoning tokens the request spent - **only at a natural close**, since a client-limited one is right-censored and enters as a key with no value. Query = cosine kNN-16, `novelty = (1 - max cos)/2`, `spread` = the weighted stdev of the neighbours' values; persisted as fp16 `.npz`. (c) **Asymmetric map** (§13.5) over running digests: `q >= q_high` -> top level, `q >= q_mid` -> middle, and the *downward* band alone is gated on novelty and spread. (d) **Everything that touched the think block is removed from this path**: the rung ladder and per-rung caps, mid-generation escalation, the quantile sketches and rank rule, the soft-limit ramp, the forced close and the loop-stall clamp. A dynamic request sets **no thinking budget at all**; the model ends its own reasoning, bounded only by the client's `max_tokens` and timeouts, and `close_kind` is `natural` or `client-limit`. The response `effort` object carries `level`, `decided`, `reasoning_tokens`, `close_kind`, `memory_entries`, `neighbours`; metrics are `vllm:effort_level`, `vllm:effort_decided`, `vllm:effort_close{kind}`, `vllm:reasoning_tokens` | Without it every dynamic request gets the same "keep it brief" sentence and a 1k cap it has to escalate out of: 12.3 % of measured natural closes were under-provisioned at the start and the p90 of what those requests wanted was 1 471 think tokens (§13.5), while the label-free kNN separates them at AUC 0.850 out of fold against 0.729 for prompt length and ~chance for entropy/margin. Cost: one extra engine step per dynamic request; the body is byte-identical across levels, so the prefix cache holds one body per conversation instead of one per (conversation, level).
